# ADR: Wails build output — what is in, and what is out

**Status:** accepted (product 1.1.0, contract v1.1.0) **Fixes:** nothing — new coverage (Providers 21 → 22).

## Context

Wails builds a desktop app from Go plus a web frontend. `wails build` runs the
frontend bundler, embeds the result into the Go binary, and writes the app to
`build/bin/`. The expensive caches behind those builds (`GOCACHE`,
`GOMODCACHE`, `node_modules`) already have providers; only the per-project
output was unreported. The question was whether it belongs, and — the harder
half — which part of `build/` may be offered.

## Decision — what is in

| id | shape | paths | why this safety |
|---|---|---|---|
| `wails` | own | `build/bin/`, `frontend/dist/` next to `wails.json` | both are generated by `wails build`; `frontend/dist` is bundler output → `safe`, `build/bin` costs a full rebuild → `caution` |

The marker is `wails.json` at the project root, so this cannot be a `TreeRule`:
a rule only sees the matched directory's parent, and `build/bin` sits two
levels below the marker. The scanner walks each root for the marker (pruning
`.git`, `node_modules`, `target`, `vendor`, `Pods`, `.dart_tool`, `.svelte-kit`)
and then inspects the two fixed child paths.

## Decision — what is out, and why

- **The whole `build/` directory.** It holds committed assets — `appicon.png`,
  the platform `Info.plist`/manifest templates — not just generated output.
  Deleting it removes files the user is expected to edit and commit.
- **Other paths under `build/`** (e.g. `build/darwin`, `build/windows`):
  templates and per-platform config, same argument. Only `build/bin` is the
  compiler's output.
- **`frontend/node_modules`** stays under the `node_modules` provider — it is
  shared across frameworks, not Wails-specific.
- **`GOCACHE` / `GOMODCACHE`** stay under `go_cache`, resolved through `go env`
  so a custom location is honoured.
- **A `wails.json` that ships inside a dependency** (`node_modules/**`) is not
  a project we own; the marker walk prunes dependency trees.

## Consequences

- One more provider id on the wire (`wails`, prefix `wa`) and one more card in
  the dashboard; no command or event changed.
- A Wails project whose output lives elsewhere (custom `-o`, or a `build/bin`
  removed by the toolchain) simply reports nothing — absence stays normal.
